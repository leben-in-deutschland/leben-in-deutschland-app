# Workflow - Decision

1. Clarify the decision to be made.
2. Read existing `docs/decisions/`, `docs/architecture/`, `docs/context/`, and `docs/memory/`.
3. Compare realistic options with pros and cons.
4. Define how to reverse only the planned documentation changes if links,
   facts, or decision state are wrong.
5. Create an ADR from `docs/decisions/_template.md`.
6. Update affected `docs/architecture/` and `docs/context/` files.
7. Verify links and consistency; use [`rollback.md`](rollback.md) if recovery is needed.
8. Update memory if the decision creates a reusable rule.
