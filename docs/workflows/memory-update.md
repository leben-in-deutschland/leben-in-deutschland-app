# Workflow - Memory Update

1. Identify the durable lesson, convention, or mistake.
2. Check existing `docs/memory/` files to avoid duplicates.
3. Define the narrow inverse edit before changing memory files.
4. Add a concise note to the most specific memory file.
5. Update or remove outdated memory when needed.
6. Verify the note is accurate and linked; use [`rollback.md`](rollback.md) if needed.
7. If the lesson changes architecture or product direction, create or update an ADR.
