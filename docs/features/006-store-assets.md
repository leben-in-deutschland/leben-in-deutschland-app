# FEAT-006: Store Screenshots, Listing Copy, and Promo Videos

Plan: [`PLAN-009`](../plans/PLAN-009-store-assets.md).
How-to: [`src/store/README.md`](../../src/store/README.md).

## Summary

A self-contained pipeline under `src/store/` captures the redesigned app
from the exported web build, frames the screens on the brand background
with short German and English captions, and produces every image the
Google Play listing needs plus the matching App Store sizes, two silent
promo videos per language, and the listing copy. The app icon stays
exactly as it is. The generated files are not committed; they are rebuilt
locally in a few minutes and checked by a script before upload.

## Motivation

The Play listing and the website still showed screenshots of the interface
before the revamp (`src/web/public/mobile/app-1..7.png`, bright green,
English captions), so the store promised a different app than the one
people installed. The owner asked for current, honest imagery for Google
Play, a ready set for a later iOS release, and a promo video if possible,
with one hard constraint: keep the existing icon. Screens had to show a
believable learner without using anyone's real data, and the work had to
be repeatable so the next UI change does not mean taking screenshots by
hand again.

## Behaviour

- `node src/store/capture.mjs` serves `src/web/out`, launches a headless
  Chromium-based browser (Microsoft Edge) over the DevTools Protocol, and
  captures eight screens – home, practice, translation, mock exam,
  progress, streak, study modes, settings – for two emulated devices
  (phone 412×915 @3×, tablet 1032×1376 @2×) in German and English, dark
  theme, with `window.CapacitorCustomPlatform = { name: "android" }` so
  the app renders its Android variant.
- The screens show a synthetic learner, "Amina" from Berlin, generated by
  `src/store/lib/demo-user.mjs` from a seeded random generator: readiness
  71 % ("Fast bereit"), 220 of 310 questions known, a 12-day streak, 7 of
  10 answers today, the exam in 21 days, three passed mock exams. The seed
  also marks the remote-content caches (`lid:notices`, `lid:questions`,
  `lid:evaluation`, see [`ADR-006`](../decisions/ADR-006-remote-content.md))
  as fresh and empty, so the capture uses bundled content and makes no
  network request.
- `node src/store/compose/render.mjs` frames each capture in a device
  shell with a fake status bar (`10:08`) and a caption, using the app's own
  fonts from the build, and writes: `play-phone` 1080×1920, `play-tablet`
  1440×2560 (used for both the 7-inch and the 10-inch slot),
  `ios-iphone-6.9` 1320×2868, `ios-iphone-6.5` 1284×2778, `ios-ipad-13`
  2064×2752, each `<set>/<lang>/NN_<shot>.png`; the feature graphic
  `play-feature/<lang>/featureGraphic.png` 1024×500; and
  `play-icon/icon.png`, a byte-identical copy of
  `src/web/public/android-chrome-512x512.png`.
- `node src/store/video.mjs` assembles, with `ffmpeg`, a silent H.264 video
  per language and orientation (`promo-<lang>-landscape.mp4` 1920×1080,
  `promo-<lang>-portrait.mp4` 1080×1920; 30 fps, about 29 s): intro card,
  eight scenes with a gentle zoom and cross-fades, outro card.
- `node src/store/check.mjs` fails with a non-zero exit when any set is
  missing or has the wrong size, format, alpha channel, file size, or
  count, when the feature graphic is not 1024×500, when the icon is not
  512×512 or differs from the committed icon, or when a video file is
  empty.
- Listing copy is committed under `src/store/metadata/android/<locale>/`
  (title, short and full description) and `src/store/metadata/ios/<locale>/`
  (name, subtitle, keywords, promotional text, description) for `de-DE`
  and `en-US`, within the stores' character limits. Only these two
  listing languages exist; the app interface is German and English, and
  the questions carry translations in seven languages.
- The website's Open Graph images `src/web/public/mobile/app-1..7.png` are
  replaced by the German Play phone slides 01–07 (the settings slide is
  not used), and `src/web/app/layout.tsx` declares them as 1080×1920.
- Committed: the scripts, templates, `metadata/`, `src/store/README.md`,
  the seven website images, and the `.gitignore` entry
  `src/store/output/`. Generated and ignored: everything under
  `src/store/output/` (raw captures, sets, feature graphic, icon copy,
  videos, frames).
- `node src/store/play-listing.mjs` sends the listing texts and the Play
  sets (phone, 7-inch and 10-inch tablet, feature graphic) to the Play
  Console through the Play Developer API with a keyless service account
  (ADR-008): a dry run needs no credentials, `--validate` uploads into a
  draft edit that Google checks and the script discards, `--apply`
  commits. Unchanged texts and byte-identical image slots are skipped, the
  icon slot is never touched, and an optional
  `metadata/android/<locale>/video.txt` sets the YouTube video. When the
  Console requires a manual review step, the commit is made without
  sending for review and the owner sends it from the Console.

## Out of Scope

- An iOS project, Xcode setup, or anything in App Store Connect. The
  `ios-*` sets and `metadata/ios/` are prepared from the same web UI so a
  later iOS release can reuse them.
- fastlane or any other upload framework. The `metadata/` layout mirrors
  fastlane's conventions, but the Play upload is the repository's own
  `play-listing.mjs`; App Store uploads are still manual.
- A new or redrawn app icon. The owner keeps the existing one.
- Captures from a real device or emulator. The screens come from the
  exported web build in Android-emulation mode.
- Store copy in further languages, or screenshots in the light theme as a
  published set (`--theme light` exists for experiments only).

## Verification

```bash
cd src/web && npm run build && cd ../..
node src/store/capture.mjs && node src/store/compose/render.mjs && node src/store/video.mjs
node src/store/check.mjs
shasum -a 256 src/web/public/android-chrome-512x512.png src/store/output/play-icon/icon.png
git --no-pager show HEAD:src/web/public/android-chrome-512x512.png | shasum -a 256
shasum -a 256 -c icon-hashes.txt   # optional: a list of all icon files hashed before the work started
for i in 1 2 3 4 5 6 7; do cmp src/web/public/mobile/app-$i.png src/store/output/play-phone/de/0${i}_*.png; done
git --no-pager status --short -- src/web/public src/android   # only mobile/app-*.png may differ for this feature
```

The three hashes must be equal, `cmp` must print nothing, and `check.mjs`
must end with "All store assets pass the size and format checks." The
`npm run build` acceptance was taken from the exported `src/web/out`
being rebuilt after the `layout.tsx` change; re-run it before a release.

## Rollback

Follow the Rollback section of

its index row. No dependency, schema, secret, deployment, or phone data is
involved.
